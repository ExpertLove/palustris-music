# История, решения, планы

## Хронология

**До 16.11.2026.** Сайт работал на Rust-бэкенде и собранном фронтенде без исходников. Пауза в строке трека
перезапускала трек, письма не уходили, часть треков не играла.

**16.11.2026 — первая помощь (на живом сайте, правкой бандла)**
- Пауза в строке трека исправлена; новая полоса прогресса; шрифт Onest.
- Почта: `relay denied` → учётка `noreply` в pmail + STARTTLS.
- «Sign in to confirm you're not a bot»: контейнер PO-токенов `bgutil-provider`, плагин yt-dlp, запасные клиенты `mweb`, `tv_simply`.
- Полное ревью сайта: безопасность, функции плеера, библиотека, баги, дизайн — стало планом переделки.

**16–17.11.2026 — переделка (коммиты `cf3fb78` … `527f788`)**
- Бэкенд: отдача трека во время загрузки (старт ~2 с вместо 9–25), предзагрузка, LRU-очистка кэша,
  `/api/stream` только после входа, cookie-сессии с истечением, выход везде, смена и сброс пароля, тексты (LRCLIB),
  история с порогом 30 с, пропуски в рекомендациях, плейлисты с порядком и публичными ссылками, поиск по всем типам,
  страницы исполнителей и альбомов, yt-dlp из pip с ночным обновлением и откатом, ночные бэкапы базы.
- Сайт написан заново (React + Vite): дизайн «Обложка задаёт цвет», эквалайзер, кроссфейд, ровная громкость,
  очередь, полноэкранный плеер, мобильная навигация, PWA, сохранение плеера между перезагрузками.
- Исправлены баги из ревью: «трека» без числа, пустая иконка «Фолк», плашка про почту, автозапуск волны, обрезанные разделы на телефоне.

**17.11.2026 — Android (коммиты `9fad5e7`, `b0526e5`, `d52ce71`)** — ведётся отдельной сессией, см. `android/AGENTS.md`.

**17.11.2026 — Android 0.2.0–0.3.0.** Эквалайзер, тексты, исполнители и альбомы, плейлисты, история, таймер сна.

**17.11.2026 — Android 0.4.0.** Новая главная (приветствие по имени, плитки быстрого доступа, недавно играло,
«Для вас», ваши плейлисты, чарт страны), 20 подборок по настроению, профиль (имя, жанры, почта, пароль, устройства,
удаление аккаунта), чарт с выбором страны. Лайки, плейлисты, история и главная работают без интернета; правки
копятся в очереди и уходят на сервер, когда появляется связь. Перетаскивание треков в плейлисте, ссылки на плейлисты

Релиз 0.4.0 сначала падал на старте: Glance тянет WorkManager 2.7.1, чьи правила R8 в строгом режиме AGP 9
не сохраняют конструктор базы. Поймали на проверке release-сборки, WorkManager обновлён явно.

**17.11.2026 — Android 0.5.0: всё, что было только на сайте.** Скорость 0,75–1,5× без смены тона (в настройках
и значок в плеере), очередь как на сайте: перетаскивание, удаление, «Очистить» (в «Моей волне» она сразу
догружается), с перемешиванием — список в том порядке, в каком треки сыграют. В «Моей музыке» вкладка
«Исполнители» и «Очистить историю». Регистрация в два шага, второй — любимые жанры для «Моей волны».
Смена скорости в последние секунды трека при включённом плавном переходе могла съесть до 12 с звука: синк Media3
сливает цепочку процессоров и сбрасывает её тем же треком, а процессор перехода принимал это за конец трека.
Теперь такой сброс считается продолжением (`CrossfadeProcessor.continuesCurrent`), проверено на эмуляторе по логу.

**17.11.2026 — рекомендации 2.0 и Android 0.6.0.** Похожее теперь берётся из радио YouTube Music (совместные
прослушивания), а не из поиска по имени исполнителя: зёрна — последние дослушанные треки, свежие лайки и самые
«свои» треки любимых исполнителей; трек, который всплывает в радио нескольких зёрен, стоит выше. Вкус считается
с учётом того, насколько трек дослушан, пропусков и «не нравится»; одного исполнителя пишут то «Шакира», то
«Shakira» — сравниваем по ключу (транслит + согласные). Новое на сервере: настройки волны (характер, настроение,
занятие), радио по треку и исполнителю, «не нравится» и скрытые исполнители, миксы дня, «Забытое любимое»,
«На повторе», статистика и итоги года; прослушивания из приложения хранят реальные секунды и время. В приложении:
плеер ездит за пальцем и уменьшается жестом «Назад», обложка перелетает из мини-плеера, смахивается вбок,
пульсирует на ударах баса; живой фон и спектр из своей аудиоцепочки (без микрофона); «Итоги года» сторис
с картинкой для «Поделиться». Найдено по ходу: обычный поиск YouTube Music больше не отдаёт длительность, и
часовые «музыка для сна» проходили в подборки как песни — для настроений и жанров теперь поиск только по песням.

**17.11.2026 — сайт догнал приложение 0.6.0.** «Не нравится» и «Не предлагать исполнителя» в меню трека
(и «Не нравится» рядом с лайком, когда играет волна, радио или микс; клавиша `D`) с «Отменить», раздел «Скрытое»,
настройки волны, радио по треку и исполнителю, миксы дня, «На повторе», «Забытое любимое», «Неделя в музыке», статистика и
«Итоги года» сторисами с картинкой 1080×1920 для «Поделиться». Два пропуска подряд перестраивают волну, как в
приложении. Сайт теперь тоже пишет в историю реальные секунды прослушивания: раньше трек, пропущенный на 40-й
секунде, шёл в статистику целиком и как «дослушанный» в рекомендации. Найдено по ходу: длинный список
исполнителей в нижнем плеере наезжал на кнопки; картинки Google на `localhost` иногда отвечают 429 —
это из-за Origin `localhost`, на боевом адресе их нет.

## Ключевые решения

| Решение | Почему |
|---|---|
| Rust + SQLite в одном процессе | сервер на 1 ядро и 600 МБ; ничего лишнего, всё в одном бинарнике |
| Сборка бэкенда на сервере | Windows-машина разработчика, кросс-компиляция под Linux сложнее, чем 1 минута сборки на месте |
| yt-dlp, а не своя загрузка | лучше всех поддерживается; лимиты YouTube одинаковы для всех библиотек |
| `visionos` первым клиентом | отдаёт тот же формат 140 без 5-секундной «рекламной» паузы tv-клиентов |
| Отдача файла во время загрузки | старт за ~2 с без полной загрузки; `Content-Length` известен заранее из `--print before_dl` |
| Cookies аккаунтов файлами, а не в базе | yt-dlp сам обновляет файл cookies, сессия живёт дольше |
| Админы через `MUSIC_ADMINS`, без UI | достаточно на двух админов; кнопку «сделать админом» владелец решил не делать |
| Фронтенд без UI-кита | свой визуальный язык, маленький бандл (~134 КБ gzip) |
| Нативный Android, не WebView/TWA | WebView глушит звук в фоне; нужны Media3, офлайн, Android Auto |
| Кроссфейд в Android — аудиопроцессором в одном плеере, не двумя плеерами | склейка до сэмпла; не нужно подменять плеер у MediaSession и делить аудиофокус |
| Офлайн в Android — JSON-файлы и очередь правок, не Room | данных мало и читаются целиком, запросов по ним нет; очередь правок (Outbox) схлопывает лайк/снятие лайка и повторные порядки |
| Кнопки виджета — через MediaController, не MediaButtonReceiver | на Android 8+ MediaButtonReceiver принимает только «играть»; нажатие на виджет разрешает запуск сервиса из фона |
| Android Auto — каталог в том же PlaybackService (MediaLibraryService) | одна сессия и один плеер для телефона, машины и виджета |
| Похожее — из радио YouTube Music (`next` + `RDAMVM`), не из поиска по имени | радио строится по совместным прослушиваниям, поиск — по названию; один запрос на зерно, кэш сутки |
| Спектр в плеере — из своей аудиоцепочки, не `Visualizer` | `Visualizer` требует разрешение на микрофон; звук и так идёт через наши процессоры, снимки привязаны к позиции трека |
| Громкость считает сервер, а не телефон | один раз на трек, с true peak; телефону не нужно декодировать весь трек заранее |
| Репозиторий публичный, но без лицензии | приватные репозитории недоступны аккаунту (ограничения GitHub); код открыт для чтения, права у владельца |

## Известные проблемы

- **Юридический риск.** Публичная регистрация + раздача аудио с YouTube. Решение владельца (например, вход по приглашениям) не принято.
- **Блокировки YouTube по IP** будут повторяться. Защита — аккаунты в админке; запасной план — прокси или загрузка на телефоне ([YOUTUBE.md](YOUTUBE.md)).
- **iPhone + эквалайзер**: Safari может прерывать звук при заблокированном экране, если включён Web Audio. В интерфейсе предупреждение. На iPhone не проверялось.
- **Бэкапы только на том же сервере** — потеря диска = потеря базы.
- **Почта не подтверждается обязательно** — поэтому админов задают только по существующим аккаунтам.
- **Поиск YouTube Music без длительности.** В обычной выдаче `duration: 0`; для подборок есть `?kind=songs`.
- **Прослушивание на сайте уходит в историю, когда трек кончился.** Если браузер убьёт фоновую вкладку
  без `pagehide` (бывает на телефонах), текущий трек в историю не попадёт.
- Основной JS-бандл ~134 КБ gzip — можно ещё разбить.
- В `smtp.conf` на сервере осталась неиспользуемая `MUSIC_COOKIES`.

## Идеи на будущее

- Внешняя копия бэкапов (S3/minio на другом хосте, Яндекс Диск).
- Поддержка прокси (WARP) для yt-dlp как ещё одна ступень после аккаунтов.
- Регистрация по приглашениям, обязательное подтверждение почты.
- Загрузка аудио на стороне Android-приложения при блокировке сервера.
- Уведомление админам (письмо / Telegram), когда IP помечен, а доступных аккаунтов нет.
- Тесты API (интеграционные) в CI.
