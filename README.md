# Музыка — music.palustris.ru

Веб-плеер: каталог YouTube Music, «Моя волна», тексты песен, эквалайзер, плейлисты с публичными ссылками, PWA.

## Структура

```
server/   бэкенд: Rust + axum + SQLite
web/      фронтенд: React 19 + TypeScript + Vite
ops/      конфиг Caddy, скрипты выкладки и обслуживания
```

### Бэкенд (`server/src`)
| Файл | Что делает |
|---|---|
| `main.rs` | API, сессии (cookie + Bearer, 60 дней с последнего входа), пароли, плейлисты, история |
| `audio.rs` | yt-dlp → кэш; отдача трека **во время загрузки**, предзагрузка, очистка кэша (LRU, лимит `MUSIC_CACHE_MAX_GB`) |
| `yt.rs` | YouTube Music: поиск по всем типам, исполнители, альбомы, плейлисты, чарты |
| `lyrics.rs` | тексты из LRCLIB с кэшем в базе |
| `recs.rs` | «Моя волна» и «Для тебя»: лайки, история, пропуски, жанры |
| `mail.rs` | письма: подтверждение почты, сброс пароля |
| `accounts.rs` | аккаунты YouTube (cookies) для yt-dlp: ротация, пауза при «not a bot», журнал загрузок `dl_events` |
| `admin.rs` | API админки `/api/admin/*`: обзор, аккаунты, журнал загрузок, логи сервера, пользователи |

Аудио: первым идёт клиент `visionos` (без «рекламной» паузы YouTube, старт ~1,5 с), дальше запасные,
два последних — с PO-токеном от контейнера `bgutil-provider` (127.0.0.1:4416).

### Фронтенд (`web/src`)
| Папка | Что внутри |
|---|---|
| `player/engine.ts` | две аудиодеки, Web Audio: эквалайзер 10 полос, предусилитель, ровная громкость, кроссфейд, анализатор |
| `player/store.ts` | очередь, перемешивание, повтор, волна, таймер сна, история/пропуски, Media Session, сохранение между перезагрузками |
| `lib/color.ts` | цвет интерфейса из обложки играющего трека |
| `components/` | плеер, полноэкранный режим, списки, карточки, меню, эквалайзер, текст, очередь |
| `pages/` | главная, поиск, медиатека, альбом, исполнитель, плейлист, настроения, топ, профиль, вход, лендинг |

## Разработка

```bash
cd web && npm install && npm run dev      # http://localhost:5173, /api проксируется на прод
cd server && cargo check                  # проверка бэкенда
```

## Выкладка

```bash
./ops/deploy-web.sh next      # фронтенд на проверочный адрес https://music.palustris.ru/next/
./ops/deploy-web.sh prod      # фронтенд в корень сайта
./ops/deploy-server.sh        # бэкенд: исходники на сервер, сборка, перезапуск
```
Перед каждой выкладкой текущая версия копируется в `/root/backups/` на сервере.

## Сервер

- `music.service` (systemd), переменные — в `/etc/systemd/system/music.service.d/*.conf`.
- Caddy: `/etc/caddy/sites-enabled/music.caddy` (копия — `ops/music.caddy`): статика + `/api` → 127.0.0.1:8030, CSP, кэш.
- yt-dlp: `/opt/yt-dlp` (venv), обновление каждый день в 04:15 (`music-ytdlp-update`, с откатом, если сломалось).
- Бэкап базы: каждый день в 04:25 (`music-db-backup`), 14 последних в `/root/backups/music-db/`.
- Почта: pmail, учётка `noreply`, отправка через STARTTLS.

## Админка — `/admin`

Видна только почтам из `MUSIC_ADMINS` (через запятую), задаётся в `/etc/systemd/system/music.service.d/admins.conf`,
после правки — `systemctl daemon-reload && systemctl restart music`.

- **Обзор**: работает ли загрузка, помечен ли IP сервера YouTube, треки за час/сутки, кэш, диск, версия yt-dlp.
- **YouTube**: аккаунты для загрузки. Cookies (Netscape `cookies.txt` или JSON из Cookie-Editor) лежат в
  `/var/lib/music/ytaccounts/{id}.txt` (0600); сохраняются только cookies youtube.com/google.com.
  Кнопка «Проверить» смотрит, видит ли YouTube вход, и пробует получить аудио тестового трека (`MUSIC_TEST_VIDEO`).
- **Загрузки**: каждая попытка yt-dlp — способ, время, итог, причина ошибки (хранится 14 дней).
- **Логи**: journalctl `music`, `caddy`, предупреждения системы, `bgutil-provider`, логи обновления yt-dlp и бэкапов.
- **Люди**: пользователи и их активность.

Порядок загрузки трека: без аккаунта (5 способов) → при «Sign in to confirm you're not a bot» IP помечается на 15 мин
и загрузка идёт через аккаунты (до трёх на трек, по очереди; аккаунт с той же ошибкой отдыхает 30 мин, с 429 — 60 мин,
с «cookies are no longer valid» — выключается до замены cookies). Пока IP помечен и аккаунтов нет, без аккаунта
пробуются только два способа, чтобы не продлевать блок. `MUSIC_ACCOUNT_CLIENTS` — свой `player_client` для попыток
с аккаунтом (по умолчанию выбирает yt-dlp).
